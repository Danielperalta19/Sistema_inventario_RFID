================================================================================
Autostart del HID en la Raspberry Pi (systemd)
================================================================================

Objetivo: al encender la pistola, sin abrir terminal, queden listos Bluetooth
(descubrible / publicidad) y el proceso gatt_server_rfid.py.

Archivos en esta carpeta:
  systemd/rfid-hid-bt-up.service  — discoverable + advertising al arrancar (antes del HID)
  systemd/rfid-hid-gatt.service   — servidor HID (después del anterior)
  systemd/rfid-hid-gatt.default   — ejemplo para /etc/default/rfid-hid-gatt

--------------------------------------------------------------------------------
1) Rutas en los .service
--------------------------------------------------------------------------------

En el repositorio las rutas usan /home/user/... (usuario Linux "user"). Si tu
Pi usa otro usuario (ej. pi), edita antes de copiar a /etc, o edita en
/etc/systemd/system/ directamente.

  systemd/rfid-hid-bt-up.service, rfid-hid-bt-up-post.service (ExecStart → sh)
  systemd/rfid-hid-gatt.service    (WorkingDirectory y ExecStart)

Si el repo en la Pi no está bajo ~/Sistema_inventario_RFID, ajusta todo el path.

--------------------------------------------------------------------------------
2) Copiar en la Pi
--------------------------------------------------------------------------------

  sudo cp systemd/rfid-hid-bt-up.service /etc/systemd/system/
  sudo cp systemd/rfid-hid-gatt.service /etc/systemd/system/
  sudo cp systemd/rfid-hid-gatt.default /etc/default/rfid-hid-gatt

  sudo nano /etc/default/rfid-hid-gatt
    # RFID_PORT=/dev/ttyUSB0  (o el puerto real del lector/emulador)
    # RFID_BAUD=115200

  sudo systemctl daemon-reload
  sudo systemctl enable rfid-hid-bt-up.service
  sudo systemctl enable rfid-hid-gatt.service
  sudo systemctl start rfid-hid-bt-up.service
  sudo systemctl start rfid-hid-gatt.service

--------------------------------------------------------------------------------
3) Comprobar
--------------------------------------------------------------------------------

  sudo systemctl status rfid-hid-gatt.service
  journalctl -u rfid-hid-gatt.service -f

Debería verse "GATT application registered" y, si hay RFID_PORT, "RFID worker started".

--------------------------------------------------------------------------------
4) Si ya tienes set-bluetooth-class.service
--------------------------------------------------------------------------------

No hay conflicto: el HID arranca después de bluetooth.service. La clase
0x000540 (teclado) puede seguir en tu otro servicio.

--------------------------------------------------------------------------------
5) Si falla con "timeout was exceeded"
--------------------------------------------------------------------------------

El unit NO depende de bluetooth.service (evita esperas raras). Tiene
TimeoutStartSec=0. Copia de nuevo `rfid-hid-gatt.service`, `daemon-reload`,
`restart`.

Antes de arrancar el servicio, no dejes otra copia del script corriendo:

  sudo pkill -f gatt_server_rfid.py

Si dos procesos registran GATT, uno falla o se bloquea.

Prueba el Python a mano (mismas rutas que en el .service):

  cd ~/Sistema_inventario_RFID/rfid_inventory/pi_ble_hid
  set -a; . /etc/default/rfid-hid-gatt; set +a
  sudo -E python3 gatt_server_rfid.py

Si aquí ves error, el fallo no es systemd sino el script o D-Bus.

Para dejar visible el Bluetooth después del arranque, ejecuta (ajusta usuario):

  chmod +x ~/Sistema_inventario_RFID/rfid_inventory/pi_ble_hid/systemd/rfid-hid-bt-up.sh
  sudo ~/Sistema_inventario_RFID/rfid_inventory/pi_ble_hid/systemd/rfid-hid-bt-up.sh

(O crontab @reboot con esa ruta.)

Si sigue mal:

  journalctl -u rfid-hid-gatt.service -e --no-pager

Comprueba que las rutas en el .service apunten a tu clon (y a user/pi) y que
exista gatt_server_rfid.py.

--------------------------------------------------------------------------------
6) Parar el modo manual
--------------------------------------------------------------------------------

Si antes lanzabas gatt_server_rfid.py a mano, no lo ejecutes dos veces:

  sudo systemctl stop rfid-hid-gatt.service   # para probar a mano
  sudo systemctl start rfid-hid-gatt.service  # volver a autostart

--------------------------------------------------------------------------------
7) Windows en el día a día
--------------------------------------------------------------------------------

Con el servicio activo, al prender la Pi solo esperas unos segundos y en la
laptop suele bastar "Conectar" al dispositivo ya emparejado (sin repetir LE
Explorer cada vez).

--------------------------------------------------------------------------------
8) Si tras reiniciar la Pi no queda "advertising" / Windows no reconecta
--------------------------------------------------------------------------------

A veces el primer rfid-hid-bt-up corre demasiado pronto o BlueZ quita la
publicidad al registrar el HID. Opcional: habilitar un SEGUNDO disparo del
mismo script DESPUÉS del GATT:

  systemd/rfid-hid-bt-up-post.service

Copiar a /etc/systemd/system/ (ajustar usuario/ruta en /etc si hace falta), luego:

  sudo systemctl daemon-reload
  sudo systemctl enable rfid-hid-bt-up-post.service
  sudo systemctl start rfid-hid-bt-up-post.service

Comprueba: sudo btmgmt -i hci0 info  (current settings: advertising, discoverable)
